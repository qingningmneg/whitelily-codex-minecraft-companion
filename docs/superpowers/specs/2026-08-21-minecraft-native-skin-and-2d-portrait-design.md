# WhiteLily 原生皮肤与 2D 立绘混合方案设计

## 1. 背景与结论

WhiteLily 的平滑 3D 模型在 Minecraft 世界中与方块环境、原版人物动作和手持物表现不协调；当前材质预览也未达到用户要求。继续投入高模、贴图、LOD、装备和动画会放大错误方向的成本。

本方案停止把自定义平滑 GLB 作为 WhiteLily 的正式世界外观，改为：

- Minecraft 世界内使用原生玩家几何与 64×64 双层皮肤；
- 桌面软件、模型库卡片和对话区域使用精致 2D 日系立绘；
- 世界行为、动作队列、立即叫停、聊天和任务执行继续独立演进，不依赖平滑 3D；
- 不使用始终朝向镜头的 2D billboard，因为它会破坏空间感，并在转动视角时显得更突兀。

## 2. 目标

1. WhiteLily 在 Minecraft 中看起来像世界原生角色，而不是外部 3D 模型被放进方块世界。
2. 保留用户原稿中的银白长发、绿色眼睛、白/浅绿/金色服装、双层裙摆、宽袖、后腰蝴蝶结和右侧百合花识别特征。
3. 继续支持 `base`、`leather`、`iron`、`gold`、`diamond`、`netherite` 六种主题。
4. 软件内以高质量 2D 立绘承载精致外观，不强迫 Minecraft 世界渲染承担同等细节。
5. 外观加载失败不得影响 Minecraft、桌面端、AI 对话、动作队列或立即叫停。
6. 用户可在模型与外观页面导入 64×64 皮肤，并可选配一张 2D 头像或立绘。

## 3. 非目标

- 不继续制作 WhiteLily 正式 high/low GLB、赛璐璐 3D 材质、3D 装备附件或专属骨骼动画。
- 不把 2D 立绘作为世界中的纸片实体。
- 不改变 Minecraft 碰撞、寻路、战斗、物品、睡眠或服务器规则。
- 不自动把 WhiteLily 专属主题套到用户导入的皮肤。
- 本次不删除既有 Blender/GLB 研究成果；先停止运行时消费，验证迁移后再单独清理。

## 4. 总体架构

### 4.1 世界内渲染

新增 `minecraft-skin` 世界渲染模式，并作为内置 WhiteLily 的默认与唯一正式世界模式。

- 复用 Minecraft 原生玩家模型、原生渲染层、原版手持物和原版动作。
- WhiteLily 身份只负责选择皮肤、经典/纤细手臂类型和六种主题，不接管几何绘制。
- 默认使用纤细手臂模型；清单必须显式记录，不能从文件名猜测。
- 世界渲染失败时回退到当前有效原生皮肤；不得取消实体本身的原版渲染。
- `SmoothMeshRenderBackend` 和正式 GLB 路由对 `builtin:whitelily` 禁用，不在启动时预加载。

### 4.2 六种主题

六种主题继续使用仓库内现有 64×64 RGBA 双层皮肤：

- `base`：无装备基础外观；
- `leather/iron/gold/diamond/netherite`：根据装备状态选择对应皮肤主题；
- 未识别或加载失败时回退 `base`；
- 主题切换只替换皮肤资源，不创建自定义 3D 盔甲轮廓。

### 4.3 桌面端 2D 立绘

内置 WhiteLily 记录独立的 `portraitAsset`：

- 立绘只以两张用户原稿为艺术事实来源；
- 模型库卡片使用完整人物缩略图；对话区可使用头像裁切；
- 卡片采用横向滚动，不因 10 个以上模型而拉伸页面；
- 图片使用 `object-fit: contain` 完整显示，不裁掉人物、头饰或裙摆；
- 2D 图片加载失败时显示稳定占位图，不影响世界连接和 AI 功能。

### 4.4 用户导入

一个用户外观条目包含：

```json
{
  "id": "user:<uuid>",
  "displayName": "自定义外观",
  "worldRenderer": "minecraft-skin",
  "skinAsset": "<validated local asset>",
  "armModel": "slim",
  "portraitAsset": "<optional validated local asset>"
}
```

- `skinAsset` 必须是合法 64×64 RGBA Minecraft 皮肤，必需基础 UV 区域不透明；
- `portraitAsset` 可选，只用于软件显示；
- 导入时先验证、复制到受管目录，再原子写入清单；
- 无 portrait 时从皮肤生成稳定的正面预览；
- 用户条目不继承 WhiteLily 六主题或专属装备映射。

## 5. 数据与接口

内置 WhiteLily 清单最少包含：

```json
{
  "id": "builtin:whitelily",
  "worldRenderer": "minecraft-skin",
  "armModel": "slim",
  "defaultTheme": "base",
  "skins": {
    "base": ".../skin/base.png",
    "leather": ".../skin/leather.png",
    "iron": ".../skin/iron.png",
    "gold": ".../skin/gold.png",
    "diamond": ".../skin/diamond.png",
    "netherite": ".../skin/netherite.png"
  },
  "portraitAsset": ".../portraits/whitelily.png"
}
```

桌面端只发送经过验证的外观 ID 和主题选择；Minecraft 端从已批准清单解析资源，不能接受任意路径。

## 6. 行为与动作

- 待机、行走、奔跑、跳跃、游泳、挥击、挖矿、钓鱼、进食、睡觉等由 Minecraft 原生实体状态和动画驱动。
- AI 行动队列继续只发布语义动作状态，不发布 GLB 动画片段名称。
- 收到“先停下来吧”“先来帮我一下”等立即叫停后，下一次有效状态更新必须退出工作动作；外观模式变化不得改变该时序。
- 换皮肤或主题不能重启已取消任务，不能中断聊天回复。

## 7. 迁移策略

1. 先增加清单和运行时 `minecraft-skin` 路由，使内置 WhiteLily 不再调用平滑 GLB 后端。
2. 验证世界内原生皮肤、六主题、动作、手持物、睡眠和立即叫停。
3. 接入桌面端 2D 立绘与用户导入的可选 portrait。
4. 从发布暂存和启动预加载中移除 WhiteLily 正式 GLB/Blender 产物。
5. 保留现有 3D 提交和源文件，直到以上验证全部通过；清理由单独提交完成，使用可恢复的 Git 记录，不直接抹除历史。

## 8. 故障隔离

- 皮肤缺失或损坏：回退上一张有效皮肤或内置 `base`。
- 立绘缺失或损坏：只替换为桌面占位图。
- 主题值非法：规范化为 `base` 并记录一次诊断。
- 自定义条目校验失败：拒绝导入，不修改当前选择。
- 任一外观故障均不得使 Minecraft 退出、桌面端白屏、AI 不回复、动作队列失效或立即叫停失效。

## 9. 验证与验收

### 自动验证

- 内置清单精确声明六张 64×64 RGBA 皮肤、`slim` 手臂和 portrait；
- `builtin:whitelily` 不触发 GLB 读取、GPU 蒙皮或自定义 shader 预加载；
- 皮肤损坏、非法主题和 portrait 失败均走预期回退；
- 模型切换原子化，失败后仍显示上一张有效皮肤；
- 动作队列与立即叫停回归测试保持通过；
- 模型库在 10 个条目下仍保持单行横向滚动和完整缩略图。

### 真实 Minecraft 验收

- 同一世界观察前、后、左右、俯视和仰视；人物与方块环境风格一致；
- 六主题可切换，手持物、行走、挖矿、钓鱼、进食和睡觉使用原版姿势且无遮挡故障；
- 外观切换、损坏皮肤回退和立即叫停不导致崩溃、卡死或对话失效。

### 视觉验收

- MC 世界内以原生皮肤为准，不再要求平滑 3D 细节；
- 软件内立绘必须完整显示银白长发、绿色眼睛、白/浅绿/金色服装、双层裙摆、宽袖、蝴蝶结和右侧百合花；
- 最终向用户展示“原稿 / 软件立绘 / MC 原生皮肤前后视”对照并取得明确确认。

## 10. 已确认决策

- 放弃 WhiteLily 正式平滑 3D 世界模型；
- 采用 Minecraft 原生皮肤 + 软件 2D 立绘；
- 不采用世界内 2D billboard；
- 现有 3D 工作先保留在 Git 历史和源文件中，迁移验证后再清理；
- 用户已将该架构选择交由 Codex 决定，按本设计继续执行。
