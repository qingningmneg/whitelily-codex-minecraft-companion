# WhiteLily PCL2 Public Beta 设计规格

日期：2026-07-27

状态：待用户审查

目标平台：Windows 10/11 x64

发布渠道：GitHub Releases Public Beta

## 1. 产品定义

WhiteLily 是面向 PCL2 用户的本地 Minecraft Java 版 AI 伙伴。用户继续用 PCL2 启动游戏、进入单人世界并开放到 LAN；WhiteLily 在本机检测到该 LAN 会话后询问是否连接。连接后，Minecraft 聊天是主要交互界面，轻量桌面控制中心负责安装引导、状态、人格、记忆、模型、安全、审计和诊断。

产品的北极星不是“自动完成任务的机器人”，而是能长期陪伴、理解玩家偏好并在明确边界内行动的 Minecraft 伙伴。默认体验偏朋友型和中等主动：它可以聊天、提醒、建议和执行小型行动，但不会主动开展大型工程。

WhiteLily 是产品名；游戏中的伙伴名称、语气和人格均可由用户修改。

## 2. Public Beta 范围

### 2.1 包含

- Windows 10/11 x64 标准安装程序。
- 安装包内置兼容的 Node.js 运行时和 Codex CLI/app-server。
- 通过 ChatGPT 登录使用 Codex，不接受 API Key 回退。
- PCL2 环境提示和本机 Minecraft LAN 自动检测。
- 仅连接 `127.0.0.1` 上、由同一台电脑开放的单人世界。
- 简体中文和英语界面。
- 动态模型选择、人格编辑、三种行为模式、三种安全预设和本地记忆管理。
- 官方验证版本清单，以及 Mineflayer 能识别但尚未验证版本的实验兼容模式。
- 本地脱敏日志、审计记录和用户手动导出的诊断包。
- GitHub Public Beta 更新提醒，下载和安装由用户手动完成。

### 2.2 不包含

- 自动操作 PCL2 或 Minecraft UI。
- 远程服务器、局域网其他电脑、公共服务器或跨设备部署。
- 基岩版、移动端、macOS 或 Linux 安装包。
- 自动下载或自动安装更新。
- 遥测、崩溃自动上传、云端记忆同步或远程控制。
- Platform API Key、按 API Key 计费的备用路径。
- Public Beta 阶段对 Minecraft 26.x 的正式兼容承诺；只有底层协议栈实际支持并通过测试后才加入清单。
- 不受预算约束的长期自主项目。

## 3. 已选方案与取舍

桌面架构采用 **Tauri 控制中心 + Node.js Sidecar**。

选择该方案的原因：

- 保留现有 TypeScript/Mineflayer/Codex 核心，避免一次性重写。
- Tauri 负责 Windows 安装、托盘、通知、单实例、进程监管和严格 IPC 权限边界。
- WebView 只承载界面，不直接获得文件、Shell、Codex 或 Minecraft 权限。
- 比 Electron 安装体积和常驻开销更小；比 WinUI 3 + Node 的双技术栈集成成本更低。

未选方案：

- Electron：开发直接，但安装体积和常驻资源更高。
- WinUI 3 + Node：Windows 原生感更强，但会引入额外 C#/C++/WinRT 集成面，不利于复用当前核心。

## 4. 系统架构

```text
Tauri WebView UI
      │ 仅允许列出的结构化命令和事件
      ▼
Tauri Rust 主进程
  ├─ 托盘、通知、单实例、安装状态
  ├─ Windows 进程/监听端口枚举
  ├─ Sidecar 生命周期监管和最终紧急终止
  └─ 版本化 IPC 校验
      │ 子进程 stdio 上的 NDJSON RPC
      ▼
Node.js Sidecar
  ├─ 会话编排与聊天路由
  ├─ 任务控制、安全策略和预算
  ├─ 人格、记忆、世界档案和审计
  ├─ Minecraft 协议探测与 Mineflayer 适配
  └─ Codex app-server 客户端与 MCP 工具网关
      │                         │
      ▼                         ▼
Bundled Codex app-server     Minecraft LAN
ChatGPT 登录与模型调用       仅 127.0.0.1
```

### 4.1 权限边界

- WebView 不可调用任意文件路径、Shell 命令、进程启动或网络地址。
- Rust 只接受版本化、可枚举、经 schema 校验的 IPC 命令。
- Rust 与 Node 通过继承的子进程 stdio 通信，不为桌面 UI 开放本地 HTTP 管理端口。
- Codex 线程保持只读文件沙箱和 `approvalPolicy: never`；游戏动作只能经过 MCP 工具网关。
- MCP 工具调用必须携带当前任务租约，并经过世界绑定、安全策略和任务预算三重检查。
- AI 输出、Minecraft 聊天和人格提示均视为不可信文本，不能修改应用配置、安全授权或桌面权限。

### 4.2 进程生命周期

- Tauri 是唯一主进程和单实例入口。
- Node Sidecar、Codex app-server 和 Mineflayer 机器人均为受监管子进程。
- 正常退出按“取消任务 → 使租约失效 → 停止移动/动作 → 断开游戏 → 停止 Codex → 停止 Sidecar”的顺序执行。
- Node 无响应时，Rust 直接终止 Sidecar 进程树，保证托盘“紧急停止”不依赖模型或 Node 事件循环继续工作。

## 5. 组件边界

### 5.1 Desktop Shell（Rust）

职责：

- NSIS 安装、首次运行、单实例和托盘菜单。
- 系统通知、语言选择和控制中心窗口。
- 枚举本机 Java/Minecraft 候选监听端口。
- 启动、监控和终止 Node Sidecar。
- 校验 UI ↔ Sidecar IPC，并把状态事件转发给 UI。

不负责：

- 解释 Minecraft 聊天。
- 生成模型提示。
- 决定具体游戏动作。

### 5.2 Session Coordinator（Node）

职责：

- 管理 `idle → detected → awaiting_confirmation → connecting → connected → reconnecting → stopped` 状态机。
- 将一个 LAN 会话绑定到一个伙伴档案、世界档案、模型选择和安全配置。
- 处理断线、限时自动重连和会话指纹变化。

该组件从现有体积过大的 `CompanionService` 中拆出，不进行无关重写。

### 5.3 Codex Gateway（Node）

职责：

- 启动内置 Codex app-server并检查 ChatGPT 登录状态。
- 完整读取分页的 `model/list` 数据。
- 向界面提供可见模型、显示名、说明、默认模型和支持的思考强度。
- 创建每个游戏会话唯一的 Codex 线程。
- 在停止、模型失效、超时或世界变化时中断当前 turn。

现有 `CodexPort.listModels(): string[]` 将演进为返回模型描述对象，不再用硬编码型号推断能力。

### 5.4 Minecraft Gateway（Node）

职责：

- 对 Rust 提供的候选端口执行 Minecraft 状态握手，只接受 loopback 地址。
- 使用 Mineflayer 连接、观察、聊天和执行原子动作。
- 把当前巨大的 `MineflayerAdapter` 拆分为生命周期、观察快照、导航和动作原语模块。

任何模块都不能绕过 `Action Executor` 直接调用破坏性 Mineflayer API。

### 5.5 Safety Kernel（Node）

职责：

- 世界授权、任务租约、动作分类、可配置预算、程序绝对上限和紧急停止。
- 将安全预设与伙伴人格完全分离。
- 为所有允许、拒绝、预算耗尽和停止操作生成审计事件。

### 5.6 Profile and Memory Store（Node）

职责：

- 伙伴档案、行为模式、模型选择、世界设置和记忆。
- 原子写入、schema 版本迁移、迁移快照与回滚。
- 敏感信息检测、记忆去重和手动增删改查。

Public Beta 继续采用小型、版本化 JSON 文件和 JSONL 审计，而不是引入跨进程原生数据库依赖。

## 6. 安装、目录与分发

### 6.1 安装包

- 使用 Tauri NSIS 生成 x64、按用户安装的 `.exe`。
- 安装包内置应用、Node.js 运行时、锁定版本的 Codex CLI、只读资源和必要许可证。
- 用户无需预装 Node、npm、Git、Codex CLI 或开发工具。
- 安装时校验内置 Sidecar 哈希；运行时不从网络下载可执行依赖。
- Public Beta 发布安装包、SHA-256 校验文件、变更记录和已验证 Minecraft 版本清单。
- 若 Public Beta 尚未获得 Authenticode 证书，发布页必须明确说明 SmartScreen 提示并提供哈希；稳定版前应完成签名。

### 6.2 数据目录

程序文件：

`%LOCALAPPDATA%\Programs\WhiteLily\`

用户数据：

`%LOCALAPPDATA%\WhiteLily\`

建议结构：

```text
WhiteLily/
  config/
    settings.json
    profiles/
    worlds/
  data/
    memory/
    migration-snapshots/
  logs/
    app.jsonl
    audit.jsonl
  diagnostics/
```

- 升级不得覆盖用户数据。
- 卸载时让用户选择保留或删除本地数据。
- 应用不读取 PCL2 凭据、Minecraft 账号令牌或 ChatGPT 认证文件内容；认证由 Codex 管理。

## 7. 首次设置

首次设置为五步向导：

1. **安装检查**：验证内置组件、WebView2、写入权限和 Sidecar 启动。
2. **ChatGPT 与模型**：启动 Codex 登录、显示账号状态，选择自动或精确模型及思考强度。
3. **伙伴人格**：设置游戏内名称、语言、引导字段、自由人格提示和主动程度。
4. **安全与世界**：选择安全预设、预算上限和世界绑定规则。
5. **连接测试**：指导用户用 PCL2 启动游戏、进入单人世界并开放 LAN，随后完成一次检测和连接。

向导可中断并恢复。完成前不自动连接世界。

## 8. PCL2 与 LAN 检测

### 8.1 PCL2 发现

PCL2 路径不得硬编码。应用按以下顺序提供提示：

1. 已运行的 PCL2 进程路径。
2. 开始菜单和桌面快捷方式目标。
3. 用户手动选择 PCL2 可执行文件。

PCL2 路径只用于环境状态和帮助文案。WhiteLily 不启动、点击、修改或注入 PCL2，因此即使 PCL2 路径未知，只要本机 Minecraft LAN 可检测，连接流程仍可继续。

### 8.2 LAN 候选发现

- Rust 使用 Windows API 枚举本机 Java/Javaw 进程的监听端口，不执行全端口扫描。
- Node 只对这些候选端口的 `127.0.0.1` 地址执行受限 Minecraft 状态握手。
- 成功握手后显示 Minecraft 版本、端口、兼容等级和拟使用的伙伴档案。
- 每个新 LAN 会话必须由用户在桌面通知或控制中心确认一次。
- WhiteLily 不扫描局域网其他主机，不接受用户输入远程地址。

### 8.3 会话与重连

- 同一进程、候选端口和握手身份保持不变时，短暂断线可在 60 秒内自动重连。
- 端口、Minecraft 进程或会话身份任一变化，都视为新会话并重新询问。
- 重连期间所有动作租约立即失效；重连成功后不自动恢复未完成的高风险动作。
- 60 秒后仍未恢复则回到等待检测状态。

## 9. 版本兼容策略

每个发布版本携带一份兼容清单：

- **官方验证**：已在可丢弃真实世界完成连接、聊天、移动、观察、背包和安全动作测试。
- **实验兼容**：Mineflayer/协议层可以识别，但 WhiteLily 未完成该版本的发布验证。
- **不支持**：协议层不能安全连接或关键动作能力缺失。

实验兼容版本：

- 首次连接必须明确标注。
- 强制从保守安全预设开始。
- 在完成该世界的兼容性检查前，禁用高风险模式。
- 发生未知方块、实体、配方或协议错误时立即停止相关任务，不猜测执行。

发布门槛是在当前依赖实际支持的范围内至少验证三个近期常用 Java 版版本，覆盖 1.20.x 和 1.21.x 系列。精确补丁版本由每次发布的真实测试结果决定，不在应用代码中永久写死。Minecraft 26.x 只有在底层依赖支持并通过相同测试后才可进入清单。

## 10. ChatGPT 登录与模型选择

### 10.1 认证

- 只使用内置 Codex 的 ChatGPT 登录流程。
- 不提供 Platform API Key 输入框，也不读取 `OPENAI_API_KEY` 作为回退。
- 登录失效、额度限制或服务不可用时暂停模型请求并提示用户。

### 10.2 模型列表

- 每次登录成功、账号变化、应用启动或用户手动刷新时调用 Codex `model/list`。
- 隐藏服务器标记为 hidden 的模型。
- 显示 app-server 返回的 `displayName`、`description`、默认标记和支持的思考强度。
- 模型名称和可用性不写死在 WhiteLily。

### 10.3 选择规则

- 默认：**自动选择**。优先采用 app-server 当前账号的默认可见模型。
- 高级：用户可为每个伙伴档案精确选择一个当前可用模型。
- 思考强度与模型分开保存，只显示该模型实际支持的选项；“自动”使用模型默认强度。
- 精确选择失效时，WhiteLily 中断当前模型 turn、使工具租约失效、提示用户并将该档案回退到“自动选择”。
- 模型切换不得在未告知的情况下继续未完成的高风险任务。

## 11. 人格与行为模式

### 11.1 人格编辑器

引导字段包括：

- 游戏内名称。
- 称呼玩家的方式。
- 语言和语气。
- 喜欢主动谈论或提醒的主题。
- 不希望提及的主题。
- 主动程度。

高级区域允许自由人格提示，但该文本：

- 有长度上限并作为不可信数据处理。
- 只能影响表达和偏好，不能覆盖安全、权限、工具预算、世界绑定和停止规则。
- 修改后只影响新 turn，不让旧任务以新人格继续。

### 11.2 三种行为模式

- **陪伴**：聊天和跟随为主；只响应玩家明确提出的行动。
- **平衡（默认）**：可根据上下文主动聊天、提醒和建议；可以执行低风险微行动，但不主动改变大量方块。
- **主动**：可在已披露目标和预算内发起小型低/中风险任务；仍不自主开展大型工程。

用户可随时切换并编辑三个模式的具体主动性参数。模式只改变互动和任务发起策略，不改变安全预设或绝对上限。高风险动作始终需要一个来自已确认主人玩家的明确目标。

## 12. 记忆设计

### 12.1 记忆来源

- 自动记忆：模型只可提交简短结构化候选；应用负责敏感信息拒绝、与原始聊天高重合拒绝、分类和去重。
- 手动记忆：用户可在控制中心新增、编辑、删除、置顶、搜索和导出。
- 不保存原始聊天全文或模型隐藏推理作为记忆。

### 12.2 记忆范围

用户可随时选择：

- **全局**：所有世界共享。
- **每世界**：只在对应世界使用。
- **分层**：全局记忆加当前世界记忆；默认采用该模式。

切换范围时：

1. 先创建只读迁移快照。
2. 对现有记忆分类、去重并生成迁移预览。
3. 用户确认模式切换后原子提交。
4. 失败时自动回滚；成功后仍保留一个可手动回退的快照。

敏感信息规则、安全设置和审计日志不参与记忆范围迁移。

## 13. 世界档案与主人身份

### 13.1 主人身份

- 桌面连接确认是配置权限的根。
- 第一次连接时，用户从当前玩家列表中确认主人 Minecraft 用户名。
- 游戏内管理命令只接受该精确用户名。
- 其他玩家聊天可作为对话上下文，但不能改变人格、安全、模型、记忆范围或世界授权。

### 13.2 世界绑定

普通保守/标准模式可只绑定当前 LAN 会话。要让高风险授权跨会话持久化，必须建立明确的本地世界绑定：

- 应用自动建议当前活跃存档目录，或让用户手动选择。
- 用户在桌面确认该存档目录。
- 应用保存规范化存档路径、PCL2 实例路径、Windows 卷序列号和存档目录文件 ID，不读取 `level.dat`、世界内容或种子。
- 存档路径、实例、卷序列号或目录文件 ID任一不匹配时，高风险授权不继承。
- 复制到新路径的世界视为新世界，必须重新授权。
- 无法取得稳定目录文件 ID 或无法无歧义识别当前活跃存档时，只允许保守/标准模式。

WhiteLily 不创建、检查、恢复或管理备份。

## 14. 安全设计

### 14.1 可调整预设

- **保守**：以聊天、观察、跟随和低风险动作优先，地形修改限制最低。
- **标准（默认）**：允许日常采集、合成、放置和导航；达到用户阈值时需要确认。
- **自由/高风险**：在特定世界持久授权后，可解锁 TNT、熔岩、火、出生点附近修改以及攻击玩家、村民或宠物等能力。

用户可调整每个世界的阈值和预算，但不能超过程序绝对上限。

### 14.2 高风险授权

启用高风险模式需要：

1. 当前世界已无歧义绑定。
2. 用户在桌面明确选择高风险模式。
3. 用户确认“我已自行备份并理解风险”。

授权可对该特定世界持久保存。程序不检查备份是否存在。高风险模式中不逐动作或逐任务弹出确认；主人在游戏内给出的明确目标即为任务授权，伙伴先在聊天中披露目标、预计动作、预算和停止条件，然后在预算内执行。

高风险模式不能由 Minecraft 聊天、人格提示或模型自行开启。

### 14.3 不可变边界

即使在高风险模式中也始终成立：

- 只能连接本机 `127.0.0.1` 上由用户确认的 LAN 会话。
- 所有任务必须绑定当前世界、主人身份和唯一租约。
- 同时最多一个活动任务。
- `!stop`、托盘紧急停止、世界变化、断线、模型失效和 Sidecar 退出都会立即使租约失效。
- 未知或歧义状态一律 fail closed。
- AI 不能修改配置、提高预算、延长租约或隐藏审计。

Public Beta 程序绝对上限：

- 每个任务最多 64 次工具调用。
- 每个任务最多 256 次方块修改。
- 每个任务累计水平移动最多 1,024 格。
- 每个任务最长 10 分钟。
- 高风险物品放置或受保护实体攻击合计最多 8 次。

用户只能设置更低的值。达到任一上限即取消任务、停止动作并在游戏聊天和桌面记录原因。

### 14.4 紧急停止

托盘“紧急停止”是最高优先级操作：

- 立即禁止新工具调用并使当前租约失效。
- 中断 Codex turn。
- 清除 Mineflayer 控制状态并断开世界。
- Node 无响应时由 Rust 终止整个受监管子进程树。

在正常运行条件下，从点击托盘紧急停止到不再产生游戏动作的目标时间不超过 2 秒。

## 15. 控制中心信息架构

侧栏：

- 首页
- 伙伴人格
- 记忆
- 世界与安全
- AI 模型
- 诊断与审计
- 设置

首页只显示：

- 当前世界和兼容等级。
- 连接/重连状态。
- 当前伙伴、行为模式、模型和记忆模式。
- 安全预设、当前任务和预算使用。
- 最近活动。
- 始终可见的紧急停止。

托盘快速菜单只包含：

- 打开控制中心。
- 连接或断开当前世界。
- 暂停或恢复主动消息。
- 紧急停止。
- 退出。

高风险模式不出现在托盘快速菜单，避免误触。

## 16. 核心数据流

### 16.1 新 LAN 会话

1. 用户通过 PCL2 启动 Minecraft 并开放 LAN。
2. Rust 枚举 Java 监听端口。
3. Node 在 loopback 上验证 Minecraft 握手和版本。
4. Session Coordinator 生成会话身份并读取兼容清单。
5. UI 显示版本、端口、兼容等级、伙伴和安全预设。
6. 用户确认连接。
7. Node 启动 Mineflayer、绑定世界档案、启动 Codex 线程。
8. 伙伴在 Minecraft 聊天中报到。

### 16.2 一次主人请求

1. Chat Router 只把主人消息识别为命令或任务授权。
2. Task Controller 创建目标、预算、停止条件和租约。
3. Prompt Builder 组合最小世界快照、人格、相关记忆和不可变安全边界。
4. Codex 通过 MCP 请求观察或动作。
5. Tool Gateway 校验租约、世界、安全策略和预算。
6. Action Executor 调用一个 Mineflayer 原子动作。
7. 结果返回 Codex，并写入脱敏审计。
8. 完成、失败、停止或超时时使租约失效。

### 16.3 自动记忆

1. turn 完成后，模型可返回零个或多个结构化记忆候选。
2. Memory Store 校验类别、长度、敏感信息、原文重合和重复项。
3. 合格项按当前记忆范围原子写入。
4. 控制中心允许用户查看、编辑、置顶、删除或导出。

## 17. 错误处理

| 情况 | 用户体验 | 安全行为 |
| --- | --- | --- |
| ChatGPT 未登录或登录失效 | 打开登录引导 | 不启动 Codex 线程，不接受 API Key 回退 |
| 模型下线或账号不可用 | 提示并回退“自动选择” | 中断当前 turn，高风险任务不自动继续 |
| 额度或服务暂不可用 | 显示暂停原因和重试入口 | 不切换到付费 API Key |
| LAN 消失 | 显示重连倒计时 | 立即使动作租约失效 |
| 发现新的端口/进程 | 重新显示连接询问 | 不沿用旧会话授权 |
| 实验版本出现未知数据 | 标明兼容错误 | 停止相关任务，不猜测方块或实体 |
| Sidecar 崩溃 | Rust 最多自动重启三次，随后提示修复 | 当前任务取消，机器人断开 |
| 本地数据 schema 无效 | 显示恢复选项 | 保留损坏文件，使用最近迁移快照，不静默覆盖 |
| 日志或磁盘写入失败 | 提示诊断不可用 | 高风险模式禁止启动，因为无法完成审计 |
| 紧急停止 | 游戏和桌面同时显示已停止 | 使租约失效，必要时终止子进程树 |

自动重启采用有界退避，单次应用运行最多三次；成功启动后也不自动恢复未完成任务。

## 18. 隐私、日志与更新

### 18.1 隐私

- 无遥测、广告标识、远程配置或自动崩溃上传。
- 只向 Codex 发送完成当前对话或任务所需的最小脱敏上下文。
- 不把原始日志、存档、PCL2 凭据或认证文件上传到项目维护者。

### 18.2 日志和诊断

- 应用日志和安全审计均为本地结构化 JSONL。
- 默认脱敏访问令牌、路径中的用户名、IP、聊天原文和疑似个人/支付信息。
- “导出诊断包”先生成预览清单，再由用户手动保存 ZIP。
- 诊断包不包含存档、认证文件、完整聊天或完整记忆内容。

### 18.3 更新

- 应用最多每 24 小时读取一次公开 GitHub Release 元数据；不发送设备标识。
- 用户可关闭自动检查并手动检查。
- 有新版时只通知并打开发布页。
- 下载、校验和安装由用户主动执行；应用不后台下载。

## 19. 测试策略

### 19.1 单元测试

- 配置 schema、IPC schema 和版本迁移。
- 模型列表过滤、自动选择、思考强度和失效回退。
- 会话状态机、60 秒重连窗口和新会话判定。
- 主人命令路由、人格不可覆盖安全规则。
- 三种行为模式和三种安全预设。
- 世界绑定、高风险持久授权和歧义时 fail closed。
- 任务租约、每项硬上限和紧急停止。
- 记忆敏感信息过滤、去重、编辑、范围迁移和回滚。
- 日志脱敏和诊断包内容白名单。

### 19.2 合同与集成测试

- WebView ↔ Rust ↔ Node 的版本化 IPC 合同测试。
- 使用伪 Codex app-server 验证登录、分页 `model/list`、turn 中断和模型消失。
- 使用伪 Minecraft 端口验证候选探测、错误协议、断线和会话变化。
- Mineflayer 适配器测试覆盖观察、移动、方块、物品、实体和控制状态清理。
- Windows 进程树、安装、启动、停止、升级和卸载生命周期测试。

### 19.3 真实环境测试

每个 Public Beta 发布候选必须在干净的 Windows 10 和 Windows 11 x64 环境中测试：

- 机器未预装 Node 或 Codex 仍能完成安装。
- ChatGPT 登录和账号模型列表正常。
- PCL2 位于默认路径、非默认路径和仅通过运行进程发现三种情况。
- 至少三个发布清单版本各使用新的可丢弃世界。
- 完成 LAN 检测、询问、连接、聊天、移动、观察、采集/放置、断线重连和紧急停止。
- 实验版本只能以保守模式开始。
- 高风险测试只在专用可丢弃世界中进行。
- 升级保留配置、人格、记忆和世界授权；卸载的数据选择正确。

### 19.4 发布门槛

- 格式检查、类型检查、全部自动化测试和 production build 通过。
- Windows 安装生命周期测试通过。
- 真实游戏兼容矩阵有日期、环境和结果记录。
- 安装包哈希、依赖许可证、SBOM 和发布说明齐全。
- 无 Critical/High 安全缺陷。
- 紧急停止在目标时间内通过测试。

## 20. 迁移与实施顺序

该设计是一个整体产品规格，但实施按可独立验证的里程碑推进：

1. **核心边界整理**：在保持现有行为的前提下拆分 Session Coordinator、Task Controller 和 Minecraft Gateway；补齐任务级预算。
2. **桌面基础**：Tauri 壳、版本化 IPC、Sidecar 监管、托盘和本地数据目录。
3. **登录与连接**：Codex 登录、动态模型描述、PCL2 提示、LAN 候选发现、连接确认和重连。
4. **产品设置**：人格、行为模式、记忆范围迁移、世界档案和安全预设。
5. **打包与发布**：NSIS、双语、诊断导出、更新提醒、Windows/真实 Minecraft 矩阵和 GitHub Public Beta。

每个里程碑都必须在进入下一个里程碑前保持现有测试通过，并增加对应验收测试。不得用一次性大重写替换已验证的 TypeScript 核心。

## 21. Public Beta 验收标准

在一台没有预装 Node/Codex 的 Windows 10 或 11 x64 电脑上，普通 PCL2 用户能够：

1. 通过一个标准安装程序安装并启动 WhiteLily。
2. 使用 ChatGPT 登录，在实时账号模型列表中选择“自动”或精确模型和思考强度。
3. 创建自定义伙伴人格，并随时切换行为、记忆和安全模式。
4. 自行用 PCL2 启动受支持 Minecraft、进入单人世界并开放 LAN。
5. 收到只针对 `127.0.0.1` 会话的连接询问，确认后在 Minecraft 聊天中与伙伴交流并执行动作。
6. 在控制中心看到世界、伙伴、模型、安全预算和审计状态。
7. 使用 `!stop` 或托盘紧急停止可靠终止动作。
8. 在模型、LAN、进程或数据异常时得到明确提示，且系统不会越过安全边界继续行动。
9. 查看和管理本地记忆，手动导出脱敏诊断包。
10. 收到更新提醒，并自行决定是否下载和安装。

满足以上条件，且第 19.4 节发布门槛全部通过，才可标记为 Public Beta 候选版本。
